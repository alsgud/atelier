You picked the look: the window and its light, North light at night, the sidebar, dark by default. It ends with numbered decisions. Read it top to bottom and answer them in one reply.

Who it’s for, and what the best tools already do

You run a team of AI agents across several projects the way a senior manager runs a team: you set direction, read plain summaries, make the few calls only you can make, and rarely debug. You look in for a minute between other things, at your desk and on your phone. The dashboard is worth it only if managing the team costs you less time than doing the work yourself.

The jobs you hire the dashboard for

  • J1
    Check in and decide. Does anything need me? If so, see it and decide in one or two taps. Most visits are this.
  • J2
    See what the team is doing. Who is working on what, is anyone stuck, is the work real.
  • J3
    Start a project. Name it, give the lead a brief, choose how much you want to approve, go.
  • J4
    Watch a task and its proof. What is it doing now, how far along, and show me it works.
  • J5
    Control spend. What did today cost, how close to the limit, how much of my own Claude plan is left.
  • J6
    Review a design or a milestone. Look at the thing itself, approve in my words or send it back.
  • J7
    Recover when something fails. What broke, what it costs me, the one thing to do about it.
  • J8
    Correct the lead. Answer, overrule, write a ruling, restart it when it drifts.

What the research says

  1. One queue, triaged by urgency, that you can empty.

    Linear’s inbox splits “Priority” from “Other”; GitHub and Superhuman sell zero as the goal. Filters and rule builders (GitHub’s notification filters, Linear’s triage rules) are for teams with thousands of items; you have tens.

    So: one Inbox, two groups (Needs you now · When you have a minute), no filters, a calm zero. J1

  2. Status is a dot and a word, from a short fixed list.

    Vercel uses five (Ready, Error, Building, Queued, Canceled), GitHub four. Nobody explains a status in a paragraph.

    So: four meanings everywhere: Working (lilac), Needs you (red), Done (green), and neutral for Waiting, Stopped, Off. Each task, desk and project uses the same words. J2 J4

  3. Progress is a shape you can see, not a counter.

    GitHub’s run graph shows jobs as boxes with durations; Devin’s progress tab lists steps with a replay timeline. “Iteration 0 of 6” says nothing (your pain point 3).

    So: a task shows its stage (Planning, Building, Checking, Review, Done), the latest step in a sentence, and “last active 2 min ago”. UX-5 J4

  4. Failures open at the failure, everything else folded.

    GitHub Actions opens the failed step’s log and folds the green ones.

    So: a failed task opens on what went wrong, in one sentence, with Retry and the log tail under Details. J7

  5. Approving shows the thing, and asks for words only when you say no.

    GitHub’s PR review puts the state beside the title and the verdict in one place; a comment is optional to approve and expected to request changes.

    So: the Inbox item shows the design, proof or question itself; rejecting asks for a note, approving a gate asks for a few words (as today, they go to the designer). J6

  6. Confirm only what can’t be undone; undo the rest.

    Vercel’s redeploy dialog names exactly what will happen and where. Linear never confirms a triage action: it offers undo.

    So: decisions are instant with Undo in the toast; stopping a lead, cancelling a task and running an audit (it spends money) ask first, in one sentence. UX-10 J1 J7

  7. The phone is a companion, not the desktop squeezed.

    Linear calls its app “the portable companion”: inbox, quick actions, swipes. GitHub Mobile shows agent sessions as a list with a status line.

    So: on the phone, Inbox, Office, project Now and the task page are first-class; Settings and Docs work but are laid out for the desk. UX-2 J1 J2

  8. Agents are teammates with a place, not log streams.

    Linear shows an agent as an assignee in the issue’s properties, with its updates in the activity. Devin’s session is a page you can come back to.

    So: every agent has a desk in the Office and every task has a page; you never read raw logs unless you open Details. UX-8 J2

  9. History is a list: status, one line, time.

    Zapier’s Zap history, n8n executions and Vercel deployments all read the same way, filterable by status.

    So: Activity is one feed by day with a project filter and “Only problems”. UX-13 J2 J7

  10. Keyboard first on the desk.

    Raycast and Linear: one palette (⌘K) to go anywhere or do anything, single keys for the common moves.

    So: ⌘K to jump to any project, task or setting; J/K, Enter, Z (undo), G then I/O/P/A to move. J1

What to avoid, all together: filter builders, avatars on every row, IDs and branch names in the first line, three-pane log views, status pills in five colours, marketing gradients and glass, and settings pages that are walls of toggles.

Where everything lives

Two levels, like Linear and Vercel: global screens across all projects (Inbox, Office, Projects, Activity, Settings) and per project pages, each with its tasks. The Inbox is home: it opens first, every time. UX-1

Global every project

  • InboxHome. Everything waiting on you, the top item open, decide in place.#/inbox · #/inbox/<item>
  • OfficeWho is working on what, one floor per project, busiest first.#/office
  • ProjectsEvery project in one sentence; New project.#/projects
  • ActivityWhat happened, by day, all projects; filter by project or problems.#/activity
  • New projectOne short form.#/new
  • SettingsYour Claude plan limits, appearance, this device, about. UX-3#/settings

A project #/p/<project>

  • HeaderName, lead on or off with its menu (Start, Restart, Stop), GitHub only when it’s wrong.
  • NowNeeds you here, working now, the phase track, the next step. UX-6
  • MoneySpent today of the daily budget, total so far.
  • TabsOverview · Tasks · Outcomes · Audits · Docs · Activity · Settings
    • DocsCharter, Rulings, Brief, Spec, Plan, Ledger, Design, Contracts, Team messages
    • SettingsApprovals, Reading, Gating, Reporting, Shipping, Budgets, Team, Lead, Numbers

A task #/t/<task>

  • StatusDot, word, reason in one sentence.
  • NowLatest step, stage, last active, spend of its budget.
  • ProofScreenshots large, recording, run log tail.
  • DockOnly when it needs you: answer, approve the plan.
  • History, Notes, FactsFolded: timeline, review, progress notes, decisions, brief, last check, files, PR.

Around every screen

  • Sign inPaste the token once per device.#/login
  • ⌘K paletteJump to any project, task, doc or setting.
  • ToastsWhat happened, with Undo where possible.
  • View portAgent-made pages and proof open in a new tab, never on the dashboard’s own origin.
  • Stale, offline, errorOne quiet line in the page; the chrome stays.

Navigation

Desk: the Y1 sidebar (≥ 1280 px)

240 px. Top: the lockup. Then the three global places with their counts, then your projects (lead dot and waiting count), then New project. The foot holds the only money on the screen: your plan and today’s spend, and the Settings gear. UX-9

Phone: top bar and tab bar (< 768 px)

Four tabs under the thumb: Inbox, Office, Projects, Activity (as today). The top bar keeps the mark, today’s spend as plain text (tap for plan and spend) and Settings. Between the two, 768–1279 px, the sidebar folds to a 64 px rail. UX-2 UX-7
